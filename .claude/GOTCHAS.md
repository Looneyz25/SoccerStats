2026-08-13 — `precomputeDisplayData` only writes `display_markets`/`display_summary` for **FT** matches; upcoming rows get none and are built client-side by `marketRowsForMatch`/`displayableMarketForKey` in page.jsx. So "count published display_markets on upcoming rows" measures NOTHING (always 0) — a hiding change for upcoming fixtures must be verified in the app, and only ships with an App Hosting rollout, not with a Firestore upload — scripts/precompute_display_markets.mjs ↔ app/dashboard/page.jsx
2026-08-13 — Clearing a market's `pick` to suppress it silently broke its own recovery path: `apply_corner_probability_cap_to_existing_prediction` looks up the price via `corner_odds_for_prediction(..., corners.get("pick"))`, so a pick-less market could never see odds arrive and republish. When nulling a field used as a lookup key, keep the original (`suppressed_pick`) and fall back to it — scripts/soccer_routine.py

2026-08-13 — `populate_pre_match_predictions` calls `save_store()` internally (soccer_routine.py), so importing soccer_routine and calling it "just to inspect" REWRITES match_data.json + predictions_<date>.json. 2026-08-13 — An unknown Sportsbet slug does NOT 404: it redirects to the parent section (or the soccer root) and still serves a valid `window.__PRELOADED_STATE__`, so a stale slug silently returns a full book for the WRONG competition (`rest-of-europe/portuguese-primeira-liga` → Czech 2.Liga; `north-america/usa-major-league-soccer` → 281 mixed events of all soccer). `fetch_page_data` now rejects any response whose resolved URL doesn't end with the requested slug. Always verify a new slug by TEAM NAMES, never by event count — scripts/soccer_fetch_sportsbet.py
2026-08-13 — `sportsbet_event_id_from_url` used an unanchored `-(\d+)(?:[/?#].*)?$`, which matches leftmost and swallows the tail, so a league slug containing a digit (`english-league-1`, `english-league-2`) parsed the event id as `1`/`2` → `find_event` returned None → ZERO deep markets (BTTS/goals) for League One+Two while digit-free Championship worked. Parse ids from the final path segment only; a "fixed" slug can break an unrelated regex downstream — scripts/soccer_fetch_sportsbet.py
2026-08-13 — Python block-buffers stdout when it's a pipe, so a long routine step streamed NOTHING until exit: `get:data:sportsbet` looked hung with a zero-byte log for 300s and was killed, discarding a working run (the store is written only at the end of `main()`). run-python.js now sets `PYTHONUNBUFFERED=1`. Before killing a silent step, check whether it's buffering — scripts/run-python.js
2026-08-13 — `get:data:sportsbet` refreshes odds but never re-runs the predictor, so prices land beside predictions still seeded from the 3.0/3.2/3.0 placeholder (`bookmaker_odds_available:false`) and `soccer_fetch_pred_odds` then pins a real quote to that stale pick (Notts County draw @3.50 while the book had Leicester @2.03). 2026-08-16 — Sportsbet CANNOT settle a played match: `sportsbet_result_for_match` hardcodes `"status": "postponed_or_cancelled"` and is a postponement detector only (hence the separate `closed=` counter). So an unsettled fixture is never fixable "via Sportsbet" — forcing it there would void a real result. The settle chain is ESPN → SofaScore (skipped for an `espn:` id) → Sportsbet (postponed only) → Flashscore → LiveScore, so for an `espn:`-id fixture ESPN is the only real settler — scripts/soccer_routine.py settlement
